# Autonomous Agent Swarm Protocol

## Status

Approved operating protocol for the active research stage.

This protocol increases throughput without relaxing source quality, data
coherence, product authority, or the prohibition on premature engine work.

## Operating objective

The swarm should complete large, reviewable research waves without asking the
founder to approve routine execution. Autonomy applies inside approved scope.
It does not permit agents to alter the game constitution, invent facts, weaken
validators, or advance the project into a later phase.

The basic unit of progress is not an agent turn. It is an integrated work packet
that answers a gameplay question, preserves uncertainty, passes validation, and
lands as a coherent checkpoint.

## Studio topology

One main integrator coordinates three concurrent workers.

### Main integrator

The main integrator acts on behalf of Agents 01, 05, 09, and 10 for the bounded
research run.

It owns:

1. Selecting the next three independent work packets.
2. Assigning exclusive file ownership.
3. Supplying the canonical bookmark, schemas, identifiers, and source rules.
4. Reviewing scope before work begins.
5. Preventing two workers from editing the same file.
6. Running the complete validation suite.
7. Reconciling shared identifiers and source records.
8. Requesting red team review.
9. Integrating accepted work into `main`.
10. Publishing a concise progress checkpoint and next wave.

The integrator does not silently rewrite specialist findings to make them fit.
It returns rejected work with a named reason.

### Worker 01: Country and force research

Default ownership:

1. One country directory or one explicitly named country batch.
2. Government and political actor records.
3. Military organization and force inventory records.
4. Public fixed facilities and dated deployments.
5. Country level source and contradiction records.

This worker may not edit global schemas, the country registry, shared plan
documents, another country directory, or simulation contracts.

### Worker 02: Theater and event research

Default ownership:

1. One fully modeled theater, secondary crisis, or political event chain.
2. Historical timelines.
3. Participants and force posture observations.
4. Operational geography.
5. Political, economic, humanitarian, and alliance effects.
6. Theater source and contradiction records.

This worker may reference country ledger entities but may not create duplicate
platforms or overwrite national inventory totals.

### Worker 03: Infrastructure and world systems research

Default ownership:

1. One infrastructure domain or one bounded geographic network.
2. Public strategic nodes.
3. Regional capacities and dependencies.
4. Network aggregation proposals.
5. Industrial conversion and strategic bottleneck records.

This worker may not construct an attack guide, infer unpublished local network
detail, or substitute a facility list for a capacity network.

### Specialist reviewers

Agents 03, 04, 06, 07, 08, and 09 review only when their domain is implicated.
They do not become extra writers on the packet.

1. Agent 03 checks whether proposed representation can conserve state later.
2. Agent 04 checks political actors, institutions, alliances, and country agency.
3. Agent 06 checks force accounting, support chains, and operational meaning.
4. Agent 07 checks economy, society, energy, industry, and civilian effects.
5. Agent 08 checks whether the data can become legible map and interface layers.
6. Agent 09 performs evidence, exploit, contradiction, and completeness attacks.

## Authority boundaries

### Autonomous authority

The integrator may proceed without founder approval when all of the following
are true:

1. The work belongs to the active research stage.
2. The work answers an approved research question.
3. It uses the frozen September 1, 2025 bookmark or clearly labels a later event
   as historical trajectory rather than opening state.
4. It does not change the top 80 selection rule or strategic addition policy.
5. It follows existing schemas and source rules.
6. It preserves unknown, disputed, and estimated values honestly.
7. It does not implement simulation behavior or final interface design.
8. It introduces no new paid data dependency.
9. It passes the required validators.
10. Its file ownership does not overlap another active packet.

Routine decisions delegated to the integrator include source selection,
research order within the roadmap, packet sizing, assignment, record naming,
contradiction creation, confidence reduction, and rejection of inadequate work.

### Founder authority

Founder approval is required for:

1. Changing the game constitution or player fantasy.
2. Reopening a completed brainstorming decision.
3. Entering the game and simulation design stage.
4. Changing the canonical opening bookmark.
5. Changing the playable country cohort rule.
6. Adopting a final technical stack or interface system.
7. Removing an approved major system or theater.
8. Purchasing or depending on a material commercial dataset.
9. Materially narrowing the complete force ledger promise.
10. Resolving a design conflict where two valid options create different games.

### Veto authority

1. Agent 01 may veto breadth that creates no player decision.
2. Agent 03 may veto a representation that cannot preserve causality or
   conservation.
3. Agent 05 may veto unsourced precision, false certainty, and unmaintainable
   data.
4. Agent 06 may veto anonymous military effects and unsupported reach.
5. Agent 07 may veto military capacity that ignores national sustainment.
6. Agent 09 may veto a packet that cannot be tested, reproduced, or explained.
7. Agent 10 may veto conflicting ownership, broken validation, and a second
   source of truth.

## Phase gates

The swarm may work only inside the current phase gate.

### Research packet gate

A packet may start when it has:

1. A gameplay question.
2. An approved scope.
3. Exclusive file ownership.
4. Named inputs and schemas.
5. Minimum source expectations.
6. Acceptance checks.
7. A reviewer.
8. A defined stopping point.

### Integration gate

A packet may integrate when:

1. Every factual record has provenance and temporal scope.
2. Units of measure are not conflated.
3. Contradictions are recorded rather than erased.
4. Exact coordinates satisfy public source and gameplay value rules.
5. Mobile observations include time and expiration.
6. National inventory and theater observations are not duplicated.
7. Required machine checks pass.
8. The assigned reviewer has no blocking finding.
9. The integrator can explain what new player or simulation question the data
   will eventually answer.
10. The packet has a maintenance date or explicit static history status.

### Wave gate

A wave is complete only when all accepted packets are integrated, all rejected
packets have recorded reasons, shared identifiers reconcile, and the complete
validator suite passes on the combined repository.

### Research exit gate

The research stage may be proposed for completion only when the requirements in
`32_RESEARCH_EXECUTION_ROADMAP.md` are satisfied. The swarm cannot approve its
own transition to game and simulation design.

### Packet sizing

A packet should normally contain one of:

1. One country lane completed to an explicit depth.
2. One service level force inventory and organization pass.
3. One bounded theater time period.
4. One infrastructure domain for one region.
5. One cross country source normalization task.
6. One independent review or reconciliation pass.

A packet is too large if it cannot be reviewed from its sources and diff in one
focused session. A packet is too small if it only creates empty folders,
headings, or unsourced placeholders.

## File ownership and integration discipline

### Exclusive ownership

1. Every writable path has one active owner.
2. Shared files are owned by the integrator during the wave.
3. Workers create local source records inside their packet path.
4. The integrator promotes accepted records into shared registries.
5. Workers do not edit schemas unless the packet explicitly assigns a schema
   change.
6. Schema changes run as their own packet before dependent content packets.
7. Theater files reference country ledger identifiers and never recreate them.
8. Infrastructure records reference countries and regions through stable
   identifiers.

### Publication discipline

The founder has approved frequent direct publication to `main` during the
research and documentation stage. The integrator chooses one of two modes per
wave.

#### Nonoverlapping research mode

1. Workers may publish directly to `main` only when the integrator assigns
   exclusive, nonoverlapping paths.
2. Each write must be a coherent checkpoint that is independently reviewable.
3. Workers fetch the current file immediately before any update and verify the
   GitHub copy immediately after publication.
4. Shared registries, status dashboards, and cross packet reconciliations remain
   integrator owned.
5. A failed validator stops further publication from that packet until corrected.
6. Direct publication is never permission to rewrite another worker's path.

#### Integration branch mode

1. Production code, migrations, destructive refactors, overlapping paths, and
   semantic conflicts use isolated branches or worktrees.
2. Branch names contain the packet identifier.
3. Workers rebase on the integrator checkpoint before handoff.
4. The integrator reviews and merges accepted combined work.
5. The integrator never resolves a semantic conflict by choosing the version
   that happens to merge cleanly.

The integrator may switch any packet from direct publication to an isolated
branch when collision risk or rollback cost rises.

### Shared file rule

The following should usually be integrator owned:

1. Country registry.
2. Global source registry.
3. Research status dashboards.
4. Schemas.
5. Stage gates.
6. Decision log.
7. Coverage reports.
8. Cross country identifier maps.

## Agent waves

### Wave composition

Each wave uses three independent research packets.

Recommended recurring pattern:

1. Worker 01 advances a priority country or force ledger.
2. Worker 02 advances the theater that most depends on that country set.
3. Worker 03 advances the infrastructure network needed by both.

This pattern produces an integrated strategic slice rather than three unrelated
collections.

### Example Indo Pacific wave

1. Worker 01 reconciles Chinese naval organization and inventory as of the
   bookmark.
2. Worker 02 reconstructs the precrisis Taiwan Strait posture and exercise
   lineage.
3. Worker 03 builds the regional port, shipyard, fuel, airfield, and sealane
   capacity layer.

The integrator then audits whether the theater uses ledger entities, whether
infrastructure enables the observed operations, and whether all uncertain
identities remain uncertain.

### Wave duration

The integrator should prefer continuous work until a coherent checkpoint exists.
It should not stop merely because one agent finished early. An idle slot receives
the next independent review packet or bounded backlog item.

## Review and red team requirements

### Worker review

Before handoff, every worker checks:

1. Schema validity.
2. Source accessibility and dates.
3. Unit of measure discipline.
4. Identifier uniqueness.
5. Geometry and temporal precision.
6. Explicit unknowns.
7. No designed content presented as observed history.
8. No claim of completeness unsupported by the packet.

### Evidence review

An independent reviewer samples the claims most likely to change gameplay.

The reviewer must attempt to find:

1. Circular sourcing.
2. An interim count mistaken for a final count.
3. Sorties mistaken for airframes.
4. Peak presence mistaken for unique inventory.
5. Formation labels mistaken for equipment quantities.
6. Munitions mistaken for launchers or delivery platforms.
7. Current labels applied to historical observations.
8. Exact coordinates unsupported by the cited source.
9. Multiple names referring to the same entity.
10. One name referring to multiple entities.

### Armchair General review

At the end of each strategic slice, Agent 09 asks:

1. Does this corpus actually enable strategic choices?
2. Are important constraints represented, or only weapons?
3. Can the player understand where capability comes from?
4. Do logistics, politics, geography, and readiness constrain force totals?
5. Is the work creating depth, or merely a large list?
6. Are apparent facts actually assumptions hidden behind confident language?

### Red team severity

1. Blocking: false claim, invalid unit, duplicate entity, unsupported exact
   location, broken conservation, missing source, or stage violation.
2. Major: gameplay critical omission, stale evidence, unresolved identity,
   inconsistent taxonomy, or misleading completeness.
3. Minor: wording, metadata, optional source improvement, or nonblocking
   normalization.

Blocking findings stop integration. Major findings require correction or an
explicit open contradiction. Minor findings may enter the maintenance queue.

## Validation requirements

Every integrated wave runs:

1. The frozen top 80 validator.
2. The Justice Mission benchmark validator.
3. The research foundation validator.
4. Every validator introduced by a new corpus domain.
5. JSON and NDJSON parsing across changed files.
6. Duplicate stable identifier detection.
7. Cross reference resolution.
8. Source identifier resolution.
9. Temporal boundary checks against the bookmark.
10. Geospatial bounds and geometry checks where relevant.

Validators are quality gates, not proof of historical truth. Evidence review
remains mandatory.

An agent may strengthen a validator. It may not weaken or delete a check merely
to make its own packet pass.

## Commit and checkpoint cadence

1. Commit after one coherent packet or integration correction.
2. Do not combine unrelated countries, theaters, schema changes, and formatting
   into one commit.
3. Push an accepted integration checkpoint whenever the full suite passes.
4. Prefer several meaningful commits per research wave over one enormous dump.
5. Never create placeholder only commits to simulate velocity.
6. Commit messages state the research outcome, not that an agent worked.
7. The integrator records rejected packets outside `main` until corrected.

## Stop conditions

An agent stops its packet when:

1. The required records and review evidence are complete.
2. The packet reaches its explicit quantitative target.
3. Remaining gaps require a different packet or unavailable evidence.
4. Continued collection would add detail without changing a player decision.
5. The best available representation is explicitly unknown, estimated, or
   synthetic.

Stopping honestly at unknown is preferable to inventing precision.

## Escalation conditions

The integrator escalates only when:

1. Founder authority is required.
2. Two approved design principles conflict.
3. A source or dataset requires material spending or new legal commitments.
4. The canonical bookmark or country cohort would need to change.
5. Available public evidence cannot support an approved product promise.
6. A safety concern requires changing the representation policy.
7. Research reveals that the planned abstraction cannot conserve state.
8. The same blocking issue survives two correction attempts.

The integrator does not escalate routine source conflicts, missing values,
packet scheduling, or confidence judgments. It records and resolves those under
the existing methodology.

## Failure and recovery

1. Failed validation produces a named error and reproduction command.
2. A bad packet is reverted or quarantined, never patched with fabricated data.
3. A duplicate entity triggers identity reconciliation before more content is
   added.
4. A corrupted shared registry returns to the last passing checkpoint.
5. A stale source triggers review status rather than silent deletion.
6. A worker that repeatedly violates scope receives smaller packets and loses
   write authority to shared paths.
7. A wave blocked by one packet may integrate the two independent passing
   packets if cross references remain valid.

## Progress reporting

The integrator reports outcomes, not activity.

Each wave report contains:

1. Integrated packet identifiers.
2. Countries, theaters, and infrastructure domains advanced.
3. Accepted record counts by type.
4. Source counts by quality tier.
5. Contradictions opened, resolved, and remaining.
6. Validation status.
7. Coverage movement against the research roadmap.
8. Blocking gaps.
9. The next three work packets.
10. Commit links.

The founder should receive a question only when an escalation condition is met.
Otherwise the integrator continues into the next wave automatically.

## Autonomy loop

The default loop is:

1. Read the latest passing checkpoint.
2. Select the highest priority unblocked strategic slice.
3. Issue three nonoverlapping packets.
4. Let workers research concurrently.
5. Run worker self checks.
6. Run independent specialist and evidence review.
7. Correct blocking and major findings.
8. Integrate accepted work.
9. Run the complete validation suite.
10. Push a coherent checkpoint to `main`.
11. Publish the wave report.
12. Start the next wave unless a true escalation condition exists.

This loop replaces approval for every routine action with explicit authority,
machine gates, adversarial review, and visible checkpoints.
